Decisions

QuestionProposedWhy
What goes whereGitHub (via skillshare): skills, agents, rules, hooks, MCP · Drive: files and secretsShareable setup gets git history; secrets and personal files never touch GitHub
AlertsAlso alert when coverage dropsToday it alerts on failed or stale runs only. Removing jobs on 2 Nov raised nothing, because nothing failed
Store engineskillshare v0.30.11, pinnedYour call; it is 2 days old, so the pin is bumped deliberately
Store sign-inGitHub device code, like gh auth loginNo pasted tokens
Store repoNew private repo, or adopt one you haveYours: xixas/claude-config, found from the skill links
SharingPer skill, into a separate public repoThe store stays private; one wrong toggle can't leak everything
Chat history · loginsOff · never1.2 GB of client conversations · re-login takes a minute
Existing toolsBorrow their catalogueschezmoi gist, asb, skillshare, npx skills: all still need a backup
Risks (4)
  • A secret reaches GitHub. Store takes only known-safe file types, and a gitleaks-style scan blocks the push. Keys & logins group is never eligible.
  • Store edits from two laptops clash. Version 1 is one-way (laptop → GitHub). Pulling onto a second laptop comes later.
  • Links on Drive. rclone keeps symlinks as .rclonelink files; untested on the encrypted remote. First thing to test.
  • Catalogue goes stale. Unknown folders still appear under "Other app settings", so nothing is hidden.
Build order (2 releases)
  1. 0.5 Find: catalogue + scan, Found screen with groups and Ignore, AI folders on Drive with --links, Overview "new items found", and an alert when something that was backed up no longer is
  2. 0.6 Store: detect or install skillshare, Config Store page showing its source repo and sync state, back up ~/.config/skillshare to Drive. Sharing comes from skillshare itself.

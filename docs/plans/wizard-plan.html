Plan · Lifeboat setup + restore wizards · 2026-10-23

Setup and restore wizards

Goal: a stranger installs Lifeboat, clicks through a few standard GNOME screens and is backed up, with no rclone, no TOML. On a new laptop the same app brings everything back. Screens follow the mockups (~/.lavish/lifeboat-mockups.html), rebuilt with stock libadwaita widgets the way Pika Backup and Secrets do it.

Done when: on a clean Fedora and Ubuntu 24.04 VM-like container, the setup wizard signs in (real Google login once, by you), creates the remotes, backs up two folders + encrypted keys, writes the recovery-kit PDF; then the restore wizard on a second clean HOME finds that backup, accepts the passphrase, rejects a wrong one, and restores the files; and a second laptop set up on the same account backs up next to the first without touching its files. CI covers everything except the real Google login.

How it fits together

All decisions and rclone calls live in a new GTK-free module, so the CLI could grow lifeboat setup later and tests run in CI without a display. The wizard is a thin view.

One account, several laptops

Each laptop gets its own folder, Lifeboat/<device>/ (device = host name, editable in setup), with its own manifest.json. Encrypted data lives under Lifeboat/secure/<device>/ behind one passphrase per Google account. Without this, a second laptop's daily sync would move the first laptop's files into old versions and prune would delete them. Your current hand-made layout (Lifeboat/Documents) keeps working; the wizard only ever creates the per-device layout.

After sign-in, setup always looks for existing manifests. If any exist it asks: Restore from <device> or Add this laptop (asks for the existing passphrase and checks it, never mints a second one).

The flows (GNOME patterns)

Setup — shown instead of "Create example config"

  1. Welcome StatusPage: "Set up backup" (suggested, pill) / "Restore from a backup".
  2. Sign in: button opens Google in the browser (Gtk.UriLauncher); spinner + Cancel while waiting; Banner on failure or timeout.
  3. What to back up: SwitchRows for XDG folders with sizes (computed in a thread), "Keys and secrets" (~/.ssh, ~/.gnupg, always encrypted), "Add a folder…" (FileDialog). Daily time ComboRow.
  4. Recovery kit: generated passphrase (6×5 chars), Save PDF (outside backed-up folders; the kit name is excluded from every job) / Copy (clipboard cleared after 30 s), "I've stored it" check enables Next. The kit also lists the client ID and manual-decrypt steps, so the backup stays readable even if Lifeboat or its Google project disappears.
  5. Backing up: progress dialog (existing stream view), then "You're covered" StatusPage. Timer installed.

Restore — from Welcome or the Restore page

  1. Sign in (same as setup).
  2. Found a backup: reads Lifeboat/.lifeboat/manifest.json (host name, last run, jobs). None found → StatusPage explaining why.
  3. Passphrase: PasswordEntryRow; checked by reading a probe file through the crypt remote (a wrong one fails clearly — rclone's root listing would wrongly succeed).
  4. Choose what to restore: CheckButton rows per job, target = original folders. Restore never deletes and never overwrites a newer local file (--update); ~/.ssh and ~/.gnupg get 700/600 permissions back (Drive does not store them).
  5. Restoring → "All done", config + remotes written so backups continue on this laptop.
